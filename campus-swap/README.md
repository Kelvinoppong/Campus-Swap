# Campus Swap

A student-only marketplace for anything students buy and sell — consoles, clothes, dorm gear, bikes, books, and tickets from campus games to conferences abroad — with .edu sign-in, real-time chat and meetup proposals.

## What's in this folder

| Path | What it is |
| --- | --- |
| `docs/BUILD_PLAN.md` | Goal, MVP scope, stack, architecture, data model, API, 10-week schedule, launch plan |
| `design/DESIGN.md` | Colors, fonts, spacing, motion and a starter `theme.ts` |
| `design/screens/` | The six screens as HTML files; open them in a browser |
| `design/images/` | Mockup photos (credits in `design/CREDITS.md`) |
| `.cursor/rules/campus-swap.mdc` | Project rules Cursor's AI reads automatically |

## Running it locally

```bash
npm install                 # from this folder; it is the npm workspace root
npm run dev:mobile          # Metro; press i for the iOS Simulator
npm run typecheck && npm run lint && npm test
```

The API additionally needs Postgres and a `.env`:

```bash
cp apps/api/.env.example apps/api/.env   # then fill in the three secrets
npm run db:up                            # Postgres + Redis via Docker
npm run prisma:migrate --workspace @campus-swap/api
npm run dev:api
```

### One gotcha worth knowing

React Native refuses to boot if two copies of React load, and several
transitive dependencies ask for a newer React than Expo SDK 57 ships. The root
`package.json` therefore pins `react` through `overrides`. If you ever see
`Cannot read property 'default' of undefined` at startup, check for a second
copy of React before anything else:

```bash
find . -path "*/node_modules/react/package.json" -not -path "*/react/node_modules/*"
```

## Hosting

Two separate deploys, both driven from this repo.

**Web app → Vercel.** `vercel.json` at the repository root builds the Expo app
for web and serves it as a single-page app. Import the GitHub repo in Vercel
and accept the detected settings; no environment variables are needed while the
app runs on demo data.

**API → Render, database → Neon.** Create a free Postgres database at
[neon.tech](https://neon.tech) and copy its connection string. Then point
Render at this repo; it reads `render.yaml`, which builds only the `api` and
`shared` workspaces. Set `DATABASE_URL` to the Neon string. The JWT secrets are
generated by Render automatically.

Note that the API refuses to start in production with `MAIL_DRY_RUN=true`, so
sending real sign-in codes needs a [Resend](https://resend.com) API key in
`RESEND_API_KEY`. Set `CORS_ORIGINS` to the Vercel URL once the app calls the
API.

## Getting started in Cursor

1. Open this folder in Cursor (File › Open Folder).
2. Open `design/screens/01-sign-in.html` in your browser to see the look.
3. In Cursor chat, start with week 1 of the plan, for example:

   > Read docs/BUILD_PLAN.md and set up the monorepo from Weeks 1–2: apps/mobile (Expo Router, TypeScript), apps/api (NestJS + Prisma), packages/shared, ESLint, Prettier and a GitHub Actions workflow.

4. Then build screens one at a time:

   > Build the sign-in screen in apps/mobile to match design/screens/01-sign-in.html, using the theme from design/DESIGN.md and react-native-reanimated for the animations.

Replace this README with the real one (store badges, demo GIF, metrics) once the app launches.
